# AstrBot 小米运动健康

这是一个为日常聊天补充生活数据的 AstrBot 插件，不是一个需要反复下指令的健康查询机器人。

配置完成后，你只需要像平时一样和 Bot 聊天。例如说“早啊，今天不太想起床”“今天好累”“刚散步回来”“还在加班”或“晚安”。当聊天内容与作息、疲劳或活动有关时，插件会在后台准备少量相关数据，让 Bot 继续按照原有模型和人格自然接话。

正常情况下，Bot 不会报出一整张数据表，也不会告诉你“刚刚调用了插件”。数据与当前话题无关、没有可用记录或不适合提及时，Bot 仍会像普通对话一样回复。直接查询数据和命令功能仍然保留，但主要用于核对数据与排查连接问题。

> 插件读取的是小米云端已经上传的历史记录，不连接手环蓝牙，也不是实时监护或医疗诊断工具。

## 可以读取哪些数据

- 步数、距离、活动消耗
- 心率
- 体重和部分身体成分
- 睡眠
- 血氧
- 压力

睡眠、血氧和压力是否可用，取决于小米账号、设备型号、所在区域以及云端实际上传的内容。没有显示某项数据，不代表设备不支持。

## 安装插件

插件支持 AstrBot 4.24.2 及以上的 4.x 版本，并要求 Python 3.11 或更高版本；发布检查覆盖 Python 3.11 和 3.12。该 AstrBot 最低版本用于保证注入聊天模型的生活数据只能作为临时上下文使用，不会写入普通会话历史。自行使用 Python 3.10 部署的旧环境需要先升级运行时。

### 从插件市场安装

插件上架 AstrBot 插件市场后，在 AstrBot WebUI 打开“插件市场”，搜索“小米运动健康”并安装。

### 从链接安装（推荐）

在 AstrBot WebUI 中打开：

“插件” → “AstrBot 插件” → “安装插件” → “从链接安装”

粘贴：

```text
https://github.com/utrgdfg/astrbot_plugin_mi_fitness_health
```

使用链接安装后，后续可以直接在 AstrBot 中检查更新。

### 从文件安装

从 GitHub Releases 下载名称形如 `astrbot_plugin_mi_fitness_health-vX.Y.Z.zip` 的正式插件安装包。不要解压，在 AstrBot 的“安装插件 → 从文件安装”中直接上传 ZIP。GitHub 自动生成的 `Source code (zip)` 不是本项目指定的安装包；如果没有看到正式安装包，请优先使用上面的仓库链接安装。

## 第一次配置

安装后，在 AstrBot WebUI 打开“小米运动健康 → 配置”。

### 第一步：取得小米账号信息

1. 在电脑浏览器打开 [小米账号中心](https://account.xiaomi.com) 并登录。
2. 按 `F12` 打开浏览器开发者工具。
3. 打开“应用/Application”或“存储/Storage”。
4. 找到 Cookies → `account.xiaomi.com`。
5. 分别复制 `userId` 和 `passToken` 的值。

`passToken` 相当于登录凭证。只能填写在你自己的 AstrBot 插件配置页里，不要发到聊天、截图、Issue 或群聊中。

### 第二步：取得 AstrBot 使用者信息

私聊你的 Bot，发送一次：

```text
/sid
```

在回复中找到：

- `UID`：代表允许使用健康数据的人。
- `Bot ID`：代表当前机器人实例。

复制这两项，稍后填写到插件配置页。这样可以确保健康数据只会出现在指定使用者与指定 Bot 的私聊中。

### 第三步：填写插件配置

配置页中最重要的项目如下：

| 配置页项目 | 应该填写什么 |
|---|---|
| 小米账号 userId（必填） | 浏览器 Cookies 中复制的 `userId` |
| 小米账号 passToken（必填、敏感） | 浏览器 Cookies 中复制的 `passToken` |
| 使用者 UID（必填） | `/sid` 回复中的 `UID` |
| 机器人 Bot ID（必填） | `/sid` 回复中的 `Bot ID` |
| 小米健康云区域（可选） | 不确定时先留空；自动识别失败后再选择 `cn` 等区域 |
| 用户所在时区 | 中国大陆通常保持 `Asia/Shanghai` |
| 在日常对话中使用生活数据 | 保持开启；让插件识别与作息、疲劳和活动有关的聊天线索 |
| 允许聊天模型接收生活数据摘要 | 必须主动开启；让当前聊天模型收到与话题有关的少量数据 |
| 允许主动判断模型读取最近私聊 | 默认关闭；只在确实需要主动关心功能且信任所选模型时开启 |
| 日常对话数据方式 | 可选择当前主模型预判、独立判断模型或本地轻量规则；兼容模式保持升级前行为 |
| 生活数据调用判断模型 | 仅用于独立判断模型模式；结合最近对话语义判断本轮是否需要数据 |
| 判断模型等待时间 | 当前主模型预判和独立判断模型共用；默认 8 秒，可在 3～30 秒之间调整，超时后本轮静默跳过数据 |
| 调用判断读取的最近消息条数 | 默认 8 条；设为 0 时判断模型只看当前消息 |
| 调用判断包含 Bot 最近回复 | 默认开启；关闭后判断模型只读取最近的用户文字 |
| 生活数据调用判断提示词 | 已提供默认内容；当前主模型预判和独立判断模式都用它补充语义分类规则 |
| 对话云端刷新等待时间 | 默认 5 秒，可在 0～30 秒之间调整；0 秒表示只后台刷新，超时后同步仍继续 |
| 补充回复草稿使用的模型、人格 | 可选；配置后会把相关生活数据摘要发送给所选模型生成草稿，请只选择信任的服务 |
| 开启主动关心检查 | 定期检查已有本地数据与近期私聊活动；不会因此读取小米云 |
| 开启普通自动同步 | 默认关闭；只有确实需要固定周期读取小米云时再开启 |
| 主动关心使用的模型、人格 | 模型先判断是否该发送，再按所选人格生成措辞；跨模型服务时不会自动转交当前人格全文 |
| 深夜主动关心判断提示词 | 已提供默认内容；可修改哪些情况应保持安静或允许关心 |
| 主动判断的上下文来源 | 可选当前 LLM 对话历史、平台真实私聊流水或混合模式；默认使用当前对话历史 |
| 主动判断读取的最近消息条数 | 默认 8 条，可在 0～50 条之间调整；0 条会让主动关心保持静默 |
| 主动判断的上下文注入提示词 | 已提供带 `{{context_lines}}` 占位符的默认内容，可调整模型理解上下文的方式 |
| 主动判断是否包含 Bot 自身消息 | 默认开启，便于判断 Bot 是否刚说过晚安或已经表达过相同关心 |

其他项目可以先保持默认值。保存配置后，重新加载插件。

### 第四步：完成首次连接

首次配置完成后，私聊 Bot 发送一次：

```text
/健康连接
```

连接检查会静默转到后台，检查期间仍可正常聊天；完成后只在当前私聊发送一次成功、失败或超时结果。连接成功后可以再发送一次 `/健康同步`，让插件读取最近的数据。之后日常聊天不需要重复这些命令。

## 平时只要正常聊天

同时开启“在日常对话中使用生活数据”和“允许聊天模型接收生活数据摘要”后，不需要改变聊天方式，也不需要先问某项数据：

- 早起、犯困、疲惫、休息或晚安等话题出现时，插件可以准备最近的作息数据。
- 散步、锻炼或刚运动回来等话题出现时，插件可以准备相关活动数据。
- 深夜仍在聊天或提到加班时，Bot 可以结合当前语境自然回应。

这些数据只是给 Bot 的背景信息，不是要求 Bot 每次都引用。是否融入回复、怎样表达，仍由当前聊天模型和人格决定；最理想的效果是回复更贴近用户近况，而不是变成数字播报。

“当前主模型预判”会在正式回复前，使用当前聊天所选的模型服务读取受限的最近文字对话和当前消息，先做一次不含小米数据的严格 JSON 语义判断。判断需要数据后，插件才检查相关缓存，并在缓存较旧时按配置限时等待小米云；取得记录后只把本轮相关的临时最小摘要交给正式回复，不替换人格，也不调用补充回复草稿模型。没有取得数据、判断失败或超时时，本轮静默跳过数据并继续正常聊天。该模式会增加一次模型调用；为避免私密摘要被同一轮其他工具带走，成功注入摘要后，本轮正式回复不会再获得其他 LLM 工具。若 AstrBot 使用 Dify、Coze 等外部 Agent 执行器、配置了回退聊天模型，或为当前模型开启联网搜索、代码执行等服务端原生工具，插件会为避免摘要离开受保护的本地对话流程而静默跳过本轮数据。

“独立判断模型”会像一个只负责路由的工具调用判断器：读取受限的最近文字对话和当前消息，按语义决定本轮是否需要生活数据，并选择最多两个相关类别，例如睡眠或活动。判断需要后，插件再准备最小摘要交给当前聊天模型。判断模型不会收到本轮刚读取的小米数据，也不会替 Bot 生成回复。模型失败、超时或输出无效时，本轮直接跳过数据。“本地轻量规则”不增加模型调用，但可能漏掉含蓄或依赖前文的表达。

插件会先检查本地已有数据。当前主模型预判和独立判断模型默认最多等待 8 秒，可在配置页调整为 3～30 秒；需要刷新时，当前回复默认最多等待小米云 5 秒，可调整为 0～30 秒。设为 0 时当前回复不等待，只启动后台刷新；其他数值超时后也会立即继续回复，已开始的同步不会被取消。独立判断或本地规则模式如果另外配置了补充回复草稿模型，它最多再占用 2 秒；当前主模型预判模式不会调用该草稿模型。小米云正在执行连接、同步或诊断时，本轮直接使用缓存或跳过数据，不在前台排队。“刚同步”“最新”“刷新”等说法仍受至少 60 秒的安全冷却和近期失败退避限制，避免频繁请求触发小米风控。小米手机端仍需先把手环数据上传到云端，插件无法代替手机完成蓝牙同步。

普通同步首次按配置范围读取数据，之后会从各类别最后一条有效记录附近增量补取，并保留两天重叠范围处理延迟上传和修正。单个数据类别读取超过 30 秒时只跳过该类别，不会拖住其他类别；登录与区域识别使用独立连接时限，不占用数据下载预算。

睡眠按本地“起床时间”归属日期。早安、刚醒和起床等对话只把以今天起床时间结束的记录视为今日睡眠；如果小米云暂时只返回昨天的最近记录，自然对话会静默跳过睡眠数据，让 Bot 按原话题正常回复，不会向用户解释同步、缓存或数据缺失。明确使用排查命令时仍可查看最近历史记录和同步状态。睡眠汇总通常比心率、血氧等单点数据更晚生成，因此同一次同步中可能暂时出现其他数据已有今天记录、睡眠仍只有昨天记录。

当日常对话判断确实需要生活数据时，AstrBot 前端日志会显示一条脱敏运行报告：最近一次云端同步仍在刷新间隔内时提示“使用本地缓存”，但不暗示所有类别都已有今天的新记录；需要访问小米云时显示“正在拉取”和“拉取成功”或脱敏后的失败状态。普通对话不需要生活数据以及主动关心后台检查时不会输出这些提示；日志只标明数据类别，不会记录账号、Token、聊天原文或具体身体数值。

如果需要确认插件读到的内容是否正确，仍可临时直接询问睡眠、活动或心率，也可以使用文末的排查命令。这些不是日常使用的必要步骤。

## 主动关心是怎样工作的

主动关心需要同时开启“主动关心检查”“允许聊天模型接收生活数据摘要”和独立的“允许主动判断模型读取最近私聊”。插件会按照配置页中的间隔检查已有本地数据与近期私聊活动，但不会仅为这项检查读取小米云。没有最近私聊授权时，主动关心保持静默；日常对话的数据增强不受影响。如果希望无论是否聊天都按固定周期读取云端，可以另外开启默认关闭的“普通自动同步”。

插件不会根据心率、血氧或睡眠分数判断疾病，也不会发送“健康异常警报”。规则只负责找出候选时机，例如在设定的深夜时段内，使用者最近确实还在和 Bot 私聊；之后“主动关心使用的模型”会按照默认的“深夜主动关心判断提示词”，结合配置数量的最近文字私聊做最后判断。用户刚说要睡觉、已经道过晚安、对话已经结束、机器人刚表达过相同关心，或者模型拿不准时，都应该保持安静。

主动判断可以读取当前 AstrBot LLM 对话历史、平台记录的真实私聊流水，或合并两者。混合模式会去除重复文本；平台流水记录必须包含可核验的私聊类型或完整会话标识，无法证明来自指定私聊时会被跳过并回退到当前对话历史。无论选择哪种来源，都只处理已验证所有者私聊中的文字，最多 50 条且总计不超过 4000 字符；图片、工具结果和系统消息不会传给判断模型。

只有判断结果为严格的 `send_care=true`，插件才会再次调用该模型按所选人格生成最终措辞。判断模型不可用、输出异常、没有可用上下文或返回不发送时，插件不会退化成固定模板消息。

主动消息只会发到已经验证过的使用者私聊。QQ 官方 API 适配器不支持这种主动发送方式；NapCat/AIOCQHTTP 等适配器通常可以使用。普通对话查询不受这个限制。

## 步数或卡路里和手机显示不一致

小米手机可能同时使用手机传感器和手环计步，并在手机本地合并结果；这个合并结果不一定完整上传到小米云，所以插件看到的步数、距离或活动消耗可能不同。

小米手机用户可以尝试：

1. 打开手机上的“小米运动健康”。
2. 在数据来源或权限设置中，关闭“手机步数”“手机活动数据”“运动与健身”或“身体活动”等手机计步来源。
3. 保留手环作为活动数据来源。
4. 重新打开小米运动健康，完成一次手环同步。

不要停用或卸载整个小米运动健康应用，它仍然负责把手环数据同步到小米云。已经在手机本地合并的历史记录不一定会重新上传，通常从调整后的当天起更准确。

## 查不到睡眠、心率或其他数据

按下面顺序检查：

1. 先在小米运动健康手机端确认对应数据已经出现。
2. 在手机端手动完成一次云同步。
3. 等待几分钟后，使用 `/健康同步` 重新读取云端记录。
4. 仍然没有数据时，使用 `/健康诊断` 查看各类云端数据是否有记录。

小米云可能延迟上传。插件显示的“数据采集时间”是设备记录时间，“同步完成时间”是插件读取云端的时间，两者不同是正常现象。

## 隐私说明

- 健康数据只允许配置的使用者在指定 Bot 私聊中读取，群聊不会显示。
- “允许聊天模型接收生活数据摘要”默认关闭。开启后，各模式只把与本次话题有关的最少摘要交给正式聊天模型；当前主模型预判阶段只读取受限文字对话，不读取健康摘要。独立判断或本地规则模式如果配置了“补充回复草稿”模型或人格，同一摘要还可能发送给该草稿所使用的模型服务；当前主模型预判模式不会调用草稿模型。第三方服务可能处理或保存这些内容。
- “允许主动判断模型读取最近私聊”是另一项默认关闭的独立授权。只开启生活数据摘要授权，不会自动允许关心模型读取聊天历史。
- 如果选择“生活数据调用判断模型”，该模型会处理配置条数内的最近所有者私聊文字、可选的 Bot 回复以及当前消息；系统消息、工具结果、图片和附件不会发送。Bot 过去的回复可能含有此前对话中谈到的个人信息，因此请只选择你信任的模型服务。判断阶段不会收到本轮刚读取的小米生活数据。
- 当前主模型预判模式不会把生活数据放进 Tool Result：预判只处理受限文字，命中后生活摘要通过 `mark_as_temp()` 临时内容块提供给正式回复，并撤销本轮其他工具。插件还会在 AstrBot 处理模型结果前拒绝该无工具请求中凭空出现的工具调用；运行时不支持这项隔离时，本轮不会注入数据，从而避免原始摘要进入普通对话历史、Tool 日志或工具参数。
- AstrBot 使用 Dify、Coze 等外部 Agent 执行器、配置了任何回退聊天模型，或为当前模型开启联网搜索、代码执行等服务端原生工具时，本插件不会向普通对话注入生活摘要；普通回复仍可按 AstrBot 自身流程执行，但这些执行器、回退服务或原生工具不会从本插件收到这份摘要。
- AstrBot 的 DEBUG、Trace 或第三方日志插件可能记录普通模型回复；回复本身可能自然提到生活数据。正式部署不要把调试日志公开或发送给不可信人员，排查问题前请先脱敏。
- 如果另外选择了关心模型并开启最近私聊授权，该模型会处理候选时机、配置数量的最近文字私聊以及生成措辞所需的相关摘要；请只选择你信任的模型服务。上下文最多 50 条、总计不超过 4000 字符，只在内存中限长组装，插件不会把这些聊天内容复制进自己的 SQLite 数据库。
- 显式选择人格和另一个模型服务时，该人格提示词会发送给所选服务；只选择其他模型而不指定人格时，插件使用内置简短风格，不会自动复制当前会话人格全文。
- 本地数据默认保留 90 天，可以在配置页调整或关闭自动清理。
- 自定义数据库路径只适合管理员使用。该位置保存未加密健康缓存，请勿选择同步盘、共享目录、公开目录或插件源码仓库；插件只接受 `.sqlite3`、`.sqlite` 或 `.db` 文件，并会拒绝符号链接及不属于本插件的现有数据库。
- 配置页把 `passToken` 显示为密码输入框，只是遮住屏幕显示，不代表加密保存。AstrBot 插件配置和本插件 SQLite 数据不会由本插件加密，应按磁盘上的明文数据保护。
- 需要更严格保护时，可将配置页中的 `passToken` 留空并通过 `MI_FITNESS_PASS_TOKEN` 环境变量提供，同时限制 AstrBot 配置目录和插件数据目录的访问权限，并为宿主机启用磁盘加密。环境变量也可能被有权访问进程或系统配置的人读取，不应视为绝对安全。
- 清除本地缓存不会删除小米云端数据，也不会自动删除插件配置中的账号信息。
- 提交 Issue 时不要附带 Cookie、`passToken`、原始健康记录或包含这些内容的截图。
